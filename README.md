# Закупщик — робот по B2B-площадкам для продаж ПО

Хакатон «ИИкузница» (Softline), задача «Робот по работе с маркетплейсами ПО», трек «Аналитик данных».
Спринт 26.11.2026 10:00 — 28.11.2026 12:00 мск (срок продлён организаторами), весь код написан в спринте.

**Стенд:** https://zakupki-robot.systemtool.ru — работает с 10:00 28.11 до 23:59 3.12.2026 (вход для жюри — в форме сдачи).

## Что делает

Цепочка из ТЗ: найти сделку → сопоставить с каталогом → выделить подходящую возможность → сформировать КП →
уведомить менеджера и объяснить, почему сделка интересна. На площадку робот ничего не подаёт — это делает человек.

```
площадки ──► сбор (каждые 5 мин) ──► префильтр без LLM ──► агент разбора ──► оценка «N из 6» ──► КП DOCX/PDF
 Портал поставщиков   адаптеры по        ПО ли это, НМЦ ≤ 1 млн,  ТЗ из вложений,     детерминированная,   по шаблону
 ТЭК-Торг, Фабрикант  config/platforms   способ, «только МСП»,    поиск по каталогу,  с разложением        Софтлайн
                                         срок; причина словами    ограничения, цитаты                       │
                                                                                                            ▼
                    менеджер: страница «Сделки» · плагин Chrome (уведомление + разбор) · письмо + Excel каждый день
```

- **Сбор.** Портал поставщиков Москвы (публичный JSON API, карточки и вложения без входа), ТЭК-Торг и Фабрикант
  (публичные списки). Новая площадка того же типа добавляется строкой в `config/platforms.yaml`. Закрытые закупки
  не сохраняются, повторный сбор не плодит дубли.
- **Префильтр** (`app/pipeline/prefilter.py`) без модели: отсекает услуги, оборудование и чужие продукты, НМЦ больше
  1 млн ₽, конкурсы и аукционы, «только для МСП», истёкший срок. Отсеивает ~94% закупок за 0 ₽, причину пишет словами.
- **Агент разбора** (`app/agent/`, промпт `prompts/analyze.md`): читает карточку и при нужде ТЗ из вложений
  (docx, pdf, doc), ищет позиции в каталоге (15,9 тыс. позиций store.softline.ru: Kaspersky, Dr.Web, PRO32,
  Astra Linux, КриптоПро, Киберпротект, РЕД СОФТ, Яндекс, Positive Technologies, Базальт, Content AI), находит
  ограничения (реестр Минцифры, «эквивалент не допускается», лицензия ФСТЭК, МСП) с дословной цитатой — код проверяет,
  что цитата есть в тексте, а `catalog_item_id` взят из ответа поиска. Инструменты только читают.
  Сопоставление и проверка ограничений (S4 и S5 в плане) объединены в один агентный цикл: так дешевле и агент видит
  ТЗ целиком.
- **Оценка «N из 6»** (`app/scoring/score.py`): ПО из каталога, НМЦ до 1 млн ₽, упрощённая процедура, оплата,
  успеваем подать, укладываемся в НМЦ по ценам каталога (нет цены — не выполнено, проверить). Приоритет внутри группы — взвешенная сумма, разложение показывается менеджеру.
- **КП** (`app/kp/`): DOCX по шаблону Софтлайн и PDF (LibreOffice в образе воркера). Артикулы и цены — с публичных
  карточек store.softline.ru (цена за пакет «на N ПК» пересчитывается в число пакетов). Где цены на сайте нет
  («Запросить цену» у отечественных вендоров) или она за диапазон узлов — ячейка пустая с заливкой, как просила
  заказчица; итог считается без неё. Цены и скидку подтверждает менеджер, подпись и печать — человек.
- **Менеджеру:** страница «Сделки» с карточкой, вкладкой «Архив» и Excel за дату или период; плагин Chrome MV3
  (`extension/`) — уведомление о горячей сделке, боковая панель с разбором по открытой вкладке, КП в один клик,
  решение менеджера; письмо по горячей сделке и ежедневный Excel в 9:00 (Yandex Cloud Postbox).
- **Решение менеджера** (карточка на стенде и панель плагина): «Беру в работу» — робот собирает КП по разбору (аналоги,
  позиции вне каталога и пустые цены тоже) и кладёт в карточку, плагин перестаёт напоминать, штамп «В работе»;
  повторное нажатие ничего не меняет. «КП отправлено» — штамп «Отправлено» с датой; без КП в карточке стенд
  предлагает собрать его или приложить своё (DOCX/PDF/XLSX до 20 МБ, робот его не пересобирает). «Не беру» —
  с причиной, она сохраняется в истории сделки, по причинам уточняют правила в «Админке». Штампы: Стоит взять,
  Нужно ваше решение, Не берём, Ещё разбираем, Отсеяна, В работе, Отправлено, Отказ, Срок вышел (взяли, но не
  отправили до конца приёма), Приём закрыт. Штамп — в карточке, списке, плагине и Excel.
- **Журнал сделки** — у каждой сделки свой (таблица `deal_status_log`, блок в карточке, последние записи в плагине,
  лист «Журнал статусов» в Excel). Строка: когда, было → стало, кто (логин менеджера или шаг робота: отбор,
  разбор агентом, пересчёт), откуда (стенд, плагин с подписью устройства, робот), причина, «N из 6», версия КП и
  файл своего КП, версия правил. Лист Excel «Итоги» — сколько сделок с каким штампом и сколько раз за период взяли
  в работу, отправили КП, отказались (по журналу).
- **Своё КП** загружается во входящую папку `data/files/_manager` (единственная, куда может писать веб-приложение),
  воркер за ~10 с переносит его в папку сделки `data/files/<площадка>/<номер>/` к документам закупки.
- **Ключи плагина** — по одному на компьютер с подписью; новый ключ старые не отключает, ненужный отзывается на
  странице «Плагин».
- **Правила** отбора и оценки — во вкладке «Админка»: правка без пересборки, версии с историей и откатом.
  `config/rules.yaml` — только первая версия для нового стенда.
- **Журнал** — последние прогоны: что нашёл на каждой площадке, сколько отсеял, сколько стоил разбор; кнопка
  «Запустить цикл» запускает сбор и разбор вне расписания (воркер берёт заявку за ≤10 с).
- **Демо-показ на ретро-данных** (панель в «Журнале», `app/pipeline/demo.py`): в назначенное время робот повторяет
  уже найденную закупку как новую сделку (те же карточка и документы, номер `…~demo…`) и ведёт её по всему конвейеру
  вживую — отбор, разбор моделью, «N из 6», письмо, уведомление плагина. Нужен для видео и питча, потому что
  подходящую закупку на площадке к нужной минуте не дождаться; заказчица разрешила показ на ретро-данных (27.11).
  Повтор подписан «демо-повтор» на стенде, в плагине и в теме письма; кнопка «Убрать демо-повторы» удаляет копии.
  От выпуска до письма ~1,5 мин, плагин опрашивает стенд раз в 30 с.
- **Журнал шагов** (`agent_step`): каждый вызов модели и инструмента с токенами, ₽ и временем.

## Запуск

Нужны Docker, Postgres 16 (на стенде — общий `shared-infra-postgres`), OpenAI-совместимый шлюз к моделям
и, если сервер вне России, выход с российским IP для госплощадок.

```bash
cp .env.example .env                       # заполнить значения
python3 scripts/store_sync.py              # выгрузка каталога в data/store/cards.jsonl (воркер импортирует сам)
mkdir -p data/files && sudo chown 10001:10001 data/files   # вложения и КП пишет воркер (uid 10001 из образа)
cd infra && docker compose --env-file ../.env up -d --build # + --profile tunnel, если нужен российский выход
curl -s https://$DOMAIN/api/status         # приложение и база в порядке
```

База и роли (один раз, под администратором Postgres; пароли — те же, что в `DATABASE_OWNER_URL` и `DATABASE_URL`):

```sql
CREATE ROLE zakupshchik_owner LOGIN PASSWORD '…';   -- владелец схемы, только для миграций
CREATE ROLE zakupshchik_app LOGIN PASSWORD '…';     -- приложение и воркер: чтение и запись, без DDL
CREATE DATABASE zakupshchik OWNER zakupshchik_owner;
```

Суперпользователь не нужен: расширение `pg_trgm` доверенное, миграция создаёт его под владельцем базы.
Проверено 27.11 с чистого клона на пустом Postgres 16: миграции, вход, все страницы, Excel, запуск воркера.

`migrate` применяет миграции Alembic под ролью владельца и завершается; `app` и `worker` работают под ролью без прав
владельца. Контейнеры non-root, файловая система только для чтения, порт наружу не публикуется (вход через Traefik).
Ночная копия БД — `scripts/backup_db.sh` (cron, восстановление описано в файле).

Проверки кода в том же образе: `docker build --target test -t zakupshchik-test . && docker run --rm zakupshchik-test`
(ruff, mypy --strict, pytest — 132 теста).

## Ограничения и заглушки

- Агент разбирает вложения только на Портале поставщиков; у ТЭК-Торга и Фабриканта — список без карточек, разбор
  по заголовку и позициям из списка.
- Берёзка и B2B-Center закрыты капчей — не подключены (план: сбор плагином из браузера менеджера).
- Входа в личные кабинеты площадок нет (по условиям задачи): только публичные страницы.
- Цена в КП пустая, если на store её нет; маржа в оценке — коэффициент-заглушка (нет закупочных цен — 0,5).
- Каталог и цены store — выгрузка 26–27.11 (`scripts/store_sync.py`, запуск вручную); наличие на складе не проверяется.
- Интеграции с CRM и 1С Софтлайн нет; Telegram и MAX не делали (по ТЗ — почта).
- Подача на площадку и подпись КП — только человек.
- Стенд на VPS в Германии: госплощадки не пускают иностранные IP, сбор идёт через SOCKS-туннель с российского ПК.
